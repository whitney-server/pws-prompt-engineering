Create a project-level .claude/ folder in the repository root if one does not exist. Populate it with knowledge files that document this project for other AI agents. Base all content on actual inspection of the codebase, git history, README, and existing docs — do not invent facts. If a fact is unknown, write TODO: rather than guessing.
Create these files:
.claude/CLAUDE.md — Entry point. State the project's purpose in one paragraph. List the tech stack, primary languages, and package managers. Give the directory layout with a one-line description per top-level folder. List the commands to build, test, lint, and run. Note any conventions an agent must follow (formatting, commit style, branch naming). Link to the other files below.
.claude/GOALS.md — The project's objectives and scope. State what the project does, who it is for, and what is explicitly out of scope. List current priorities and known non-goals.
.claude/DESIGN.md — Design history and architecture. Describe the major components and how they interact. Record key design decisions and the reasoning behind them. Note trade-offs made and alternatives rejected. Include a dependency or data-flow overview if applicable.
.claude/IMPLEMENTATION.md — Implementation history. Summarize how the codebase evolved based on git history and changelogs. List major milestones, refactors, and migrations. Note current known limitations, tech debt, and areas under active change.
.claude/GLOSSARY.md — Define project-specific terms, acronyms, and domain concepts an outside agent would not know.
Requirements: Use short, factual sentences. No marketing language or filler. Keep each file scannable with clear headings. After creating the files, print a summary of what was written and flag every TODO: left for a human to fill in.
